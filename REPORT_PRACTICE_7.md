# Отчет по практическому занятию №7

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек
*   **log_entry**: Def на строке 3 (`log_entry = "Start processing"`). Use на строке 11 (`file.write(log_entry)`). *Примечание: Def на строке 10 — мертвое присваивание.*
*   **status**: Def на строке 5 (`status = "approved"`). Use на строке 10 (в конкатенации).
*   **balance**: Def на строке 6 (`balance = get_balance(user_id)`). Use на строке 7 (`new_balance = balance - amount`).
*   **new_balance**: Def на строке 7. Use на строке 8 (`update_balance(...)`).
*   **file**: Def на строке 9 (`file = open(...)`). Use на строке 11 (`file.write(...)`).

### 1.2. Описание выявленных дефектов
*   **Дефект 1 (Неинициализированная переменная):** Переменная `status` инициализируется только внутри блока `if amount > 0`. Если `amount <= 0`, при попытке использовать `status` на строке 10 возникнет ошибка `UnboundLocalError`.
*   **Дефект 2 (Мертвое присваивание):** На строке 3 переменной `log_entry` присваивается значение "Start processing", но оно никогда не читается, так как перезаписывается на строке 10.
*   **Дефект 3 (Утечка ресурса):** Файл открывается на строке 9 (`file = open(...)`), но не закрывается (отсутствует `file.close()`), что приводит к утечке файлового дескриптора.

## 3. Деобфускация

### 3.1. Расшифрованная строка
`import os; os.system('rm -rf /')`

### 3.2. Анализ угрозы
Скрипт использует функцию `exec()` для выполнения обфусцированного Base64-кода. Расшифрованная строка вызывает системную команду `rm -rf /`, которая рекурсивно и принудительно удаляет все файлы и каталоги. Это приведет к полному уничтожению операционной системы.

### 3.3. Методы защиты
1. Избегать использования `exec()` и `eval()` для непроверенных данных.
2. Использовать статический анализ.
3. Валидация входных данных.
4. Запуск скриптов в изолированной среде.
